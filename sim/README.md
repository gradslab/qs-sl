# Simulation code

Everything behind the [project page](https://gradslab.github.io/qs-sl/) of the paper *"Quasi-Static Fault-Tolerant
Feedback Control of a Quadrotor Carrying a Slung Payload under Rotor Failure"*.

A quadrotor carries a payload on a massless rod pivoted at its center of mass. One rotor has failed completely, so
the roll torque is tied to the thrust and the yaw torque. The quasi-static feedback of the paper drives the payload
onto a horizontal circle and assigns its speed along the circle. The controller of the paper is written in MATLAB
from expressions generated by Maple (`../matlab/`). This directory holds a Python port of it, verified against the
MATLAB code, a Drake multibody simulation of the same scenario, and the scripts that produce the figures, the
numbers and the page.

## Layout

```
model/      params.py                parameters of Section VI of the paper, gains by pole placement
            translate_matlab.py      rewrites matlab/h1_.m, h2_.m, h3_.m, b_.m as qsf_gen.py (tracked)
            sls.py                   coordinate-free model (1) and the quasi-static feedback (17), (26)
            simulate_port.py         closed loop on the model, default and tight tolerances
            test_chains.py           gate: derivatives of the output chains along the closed loop
            compare_matlab.py        gate: the port against the MATLAB reference data in results/matlab
drake/      sls_plant.py             the system as a Drake MultibodyPlant, state conversions, applied forces
            verify_plant.py          gate: accelerations of the plant against the model (1)
            sim_drake.py             the closed-loop runs (scenario of the paper, hover start on the path, variants)
            render_drake.py          animations and the snapshot composite with the VTK renderer of Drake
metrics.py                           every number quoted on the page, from the logs
paper_figures.py                     Figs. 2 to 7 of the paper and the figures of the page
web/        anim_web.py, page_numbers.py, build_page.py   the project page in ../docs
results/    logs (npz), MATLAB reference data, figures, animations, numbers
```

## Reproduce everything

```sh
git clone https://github.com/gradslab/qs-sl.git
cd qs-sl/sim
bash reproduce.sh          # install -> gates -> runs -> numbers -> figures -> page
bash reproduce.sh anim     # the same, with the four animations
```

`reproduce.sh` runs the steps below. Use them individually if you prefer.

### 1. Install

Python 3.10 or newer on macOS or Linux. Drake installs from pip. The animations also need ffmpeg.

```sh
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Verification gates

`test_chains.py` integrates the closed loop over short pieces with a tight tolerance and checks that the time
derivative of every generated term equals the next term of its chain, up to the commanded sixth derivatives, which
tests the drift terms and the decoupling matrix together. `verify_plant.py` checks the Drake plant against the
model (1) at random states and inputs, with a point-mass payload, and the round trip of the state conversion.
`compare_matlab.py` evaluates the controller and the vector field at the 60 states of
`results/matlab/reference_states.npz`, written by `../matlab/reference_run.m`, and compares the closed-loop runs
of the port with the MATLAB runs, so it runs after `simulate_port.py`. Each gate records its worst value in
`results/web/gates.json`, which the page quotes. If a gate fails, nothing downstream is worth running.

```sh
python3 model/test_chains.py
python3 drake/verify_plant.py
```

The generated module `qsf_gen.py` is tracked. To rebuild it from the MATLAB files, run
`python3 model/translate_matlab.py`.

### 3. The runs

The scenario of Section VI lives in `model/params.py`. The path coordinate is the polar angle of the payload and
`V_D` is its rate, 0.8 rad/s, so the payload moves at 4 m/s along the circle.
A run writes `results/<name>.npz` with the state of the paper, the thrust, the torques, the outputs and the angles
at every controller step, and the Drake runs also the plant state.

```sh
python3 model/simulate_port.py                              # results/port_default.npz, as matlab/main.m
python3 model/simulate_port.py --tight                      # results/port_tight.npz
python3 model/compare_matlab.py                             # gate: the port against the MATLAB reference
python3 drake/sim_drake.py                                  # results/drake_run.npz, 1 kHz, spherical payload
python3 drake/sim_drake.py --start on-path --tag _onpath    # hover start on the path
python3 drake/sim_drake.py --point-mass --tag _pointmass    # payload without rotational inertia
python3 drake/sim_drake.py --hz 400 --tag _400hz            # slower controller
```

### 4. The numbers and the figures

```sh
python3 metrics.py                    # prints every number of the page
python3 paper_figures.py              # results/figs/fig_*.pdf and .png, Figs. 2 to 7 of the paper
python3 paper_figures.py --web        # results/figs/W_*.png, the figures of the page
python3 drake/render_drake.py drake_run --snapshots 0,1,1.5,2,5,6.5,8,10.5 --cam wide
```

### 5. Animations and the page

The renderer needs the VTK render engine of Drake, which the pip wheel includes, and `anim_web.py` needs ffmpeg.

```sh
for c in follow side orbit; do python3 drake/render_drake.py drake_run --cam $c; done
python3 drake/render_drake.py drake_run_onpath --cam follow
python3 web/anim_web.py        # docs/anim/*.mp4 with poster frames, two gifs
python3 web/page_numbers.py    # results/web/numbers.json
python3 web/build_page.py      # docs/index.html and docs/figs
```

**Frames.** The paper works in a north-east-down frame with the thrust along the negative third body axis. The
Drake world has its third axis up. The two are related by the rotation diag(1, -1, -1), which `drake/sls_plant.py`
applies to positions, rotations, velocities and torques. The logs carry the state in the frame of the paper.

**MATLAB reference data.** `../matlab/reference_run.m` writes CSV files, and `model/matlab_csv_to_npz.py` converts
them into `results/matlab/*.npz`. It needs the Control System Toolbox for `place` and the Robotics System Toolbox
for `rotm2eul`.
